## Reporting a vulnerability

**Please do not open a public issue for a security problem.**

Use GitHub's private vulnerability reporting instead:

➡ <https://github.com/leejongyoung/egovframe-badge/security/advisories/new>

If private vulnerability reporting is not enabled on the repository, please report through email instead of opening a public issue.

Please include:

- what is affected (badge version, generation script, or workflow)
- how to reproduce it, and the impact you expect
- anything you already did to verify it (hashes, URLs, logs)

Reports are handled privately until a fix is available; credit is given on request.

## Scope

In scope:

- Badge SVGs in [`badges/`](../badges/): generated content, embedded logo, version metadata
- Automation: [`.github/workflows/`](../.github/workflows/) and [`scripts/`](../scripts/). New badges are generated by the `generate-badges` workflow; a way to make that step produce wrong output, leak the token, or run untrusted input counts as a vulnerability.

Out of scope, please report to the owner:

- The eGovFrame framework and its download server → the eGovFrame project, <https://www.egovframe.go.kr/> and [eGovFramework](https://github.com/eGovFramework).
- GitHub itself → <https://github.com/github/github/security/policy>.
- shields.io → <https://github.com/badges/shields/security/policy>.

## Supported versions

Only what is in `badges/` on the default branch is maintained: all versions listed in `versions.json`. Badges removed when a newer patch of the same series arrived are not.

## Verifying a badge yourself

Every badge is a self-contained SVG with embedded logo. To re-generate and verify a version against the source from CI:

```bash
gh workflow run generate-badges.yml -R leejongyoung/egovframe-badge -f version=5.0.2
```
